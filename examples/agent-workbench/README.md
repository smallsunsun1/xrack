# XRack Agent Workbench

一个使用 XRack 的原生桌面会话示例。选择工作目录后，可以向本机 Codex 发消息，查看流式回复，并停止当前轮次。同一会话内的后续提问沿用相同的 Codex thread。

从仓库根目录运行。默认在 PATH 中查找已登录的 Codex CLI，也可用 `--codex /absolute/path/to/codex` 指定可执行文件。

```sh
bazel run --repo_env=CARGO_BAZEL_ISOLATED=false //examples/agent-workbench:agent_workbench -- \
  --workspace "$PWD"
```

在侧栏点项目选择器右侧的文件夹按钮添加目录。最近 32 个项目保存在 Codex 主目录的 `xrack-workbench/projects.json`，应用重启后仍可选择。点 **所有项目** 可在同一棵树中展开项目和浏览会话。展开时按需加载该项目的历史，显示已知工作树、置顶和活动状态，也可在组内加载下一页。选中一条会话才切换工作目录。点 **当前项目** 可使用搜索和归档视图。在同一个窗口切回项目时会恢复刚才打开的会话、草稿和附件。

在 **所有项目** 视图输入关键词，可搜索已登记项目和已知工作树的会话。结果带有项目名称，通过 **已归档** 可切换搜索范围，并可继续加载下一页。清空输入会回到项目树。Command/Control+K 聚焦当前侧栏视图的搜索框，命令面板的 **搜索所有项目会话** 会直接打开跨项目搜索。

在当前项目的会话列表或跨项目搜索结果中右键单击会话，可重命名、置顶、归档或恢复。聚焦会话后可按 Shift+F10 打开菜单。项目树中的会话可通过 **⋯** 打开这些操作。管理操作只作用于所选会话，当前工作目录和草稿可继续使用。

点 **新会话** 可在当前工作目录开始。重启后点击历史会话即可读回消息，下次发送会继续原来的 Codex thread。侧栏的 **更多会话** 用于按页加载列表，对话顶部的 **更早消息** 用于向前翻页。

新会话的输入区可通过 **本地目录** 选择运行位置。选择 **使用工作树** 和起始分支后，发送第一条消息才创建分离工作树，原来的草稿、附件和模型选择会用于这次发送。选择与当前 HEAD 相同的起点时，可以带上原目录的已跟踪改动。源分支变动或工作树创建失败时，输入区保留草稿，可重新选择位置后重试。

项目根目录下的 `.codex/environments/*.toml` 可以提供新工作树的可选初始化脚本。选中环境后，位置对话框会显示脚本。发送第一条消息时，工作台创建工作树并执行已预览的脚本，再把消息发给 Codex。初始化失败会保留草稿，可查看输出并在同一工作树重试。重新发送前，工作台会检查待执行的脚本是否仍与所选版本一致。

空闲会话可通过标题栏 **⋯ → 交接会话** 在本地目录和关联工作树之间切换。第一次从本地交接时，会创建当前提交的分离工作树。之后会复用该会话关联且仍可用的工作树。表单显示目标目录，可选择复制未提交的已跟踪改动。Git 会检查补丁是否能应用，出现冲突时可处理后重试。交接后沿用同一 Codex 会话，后续轮次使用新目录。

在仓库根目录放置 `.worktreeinclude`，可按 Git 忽略规则的语法指定新工作树需要的本地配置。匹配文件必须是源目录中被 Git 忽略的未跟踪文件。被忽略的 `AGENTS.override.md` 会自动带入。新会话、会话分支和交接创建的独立工作树都应用这项规则。遇到源符号链接或目标已有文件时会跳过对应路径。

```gitignore
/.env.local
/config/*.local.json
!/config/private.local.json
```

当前会话运行时，可以切换项目、阅读其他会话或发起另一轮任务。侧栏会标出 **运行中**、**待确认** 和后台完成后的 **有更新**。选择对应会话即可继续阅读、回答问题或停止该会话的一轮任务。遇到需要确认的问题，也可以点 **稍后回答** 暂时收起弹窗。

点侧栏 **活动**，或按 Command/Control+Alt+U，可查看工作台当前跟踪的跨项目会话。可以按待确认、有更新和运行中筛选，点一项打开会话。Command/Control+Alt+A 跳到下一个待确认会话。**全部标为已读** 或 Shift+Esc 清除本机工作台的更新标记，运行中的任务和待确认的问题仍会显示。

macOS 上可用应用包启动工作台，接收系统通知。`agent_workbench_macos_bundle` 由 `rules_apple` 链接和签名。以下启动目标会打开该应用包，并传递当前工作目录和 Codex 环境。

```sh
bazel run --repo_env=CARGO_BAZEL_ISOLATED=false //examples/agent-workbench:agent_workbench_macos -- \
  --workspace "$PWD"
```

用 `bazel build --repo_env=CARGO_BAZEL_ISOLATED=false //examples/agent-workbench:agent_workbench_macos_bundle` 生成标准应用归档。启动目标接受 `--prepare-only`，可以只解包并取得 `.app` 路径。

从活动页的 **通知** 或命令面板打开 **通知设置**。默认关闭。可以让任务结束时仅在工作台位于后台提醒，或始终提醒。待确认提醒单独设置。首用时点 **允许通知**，由 macOS 请求权限。点当前实例发出的通知会打开对应会话。

打开过多个会话后，可用标题栏的前进、后退按钮浏览访问记录。Command/Control+[、Command/Control+] 和鼠标侧键也可触发。访问记录包含项目切换。回到旧会话时会恢复它的草稿、附件和阅读位置。从历史中的会话打开新会话或另一个项目时，会从当前位置开始新的访问路径。

同一窗口打开多个会话时，标题上方会显示会话标签，支持跨项目切换、拖动排序和关闭。用 **Ctrl+Tab** 和 **Ctrl+Shift+Tab** 切换相邻标签。**Command/Control+W** 关闭当前标签并切到相邻会话，**Command/Control+Shift+T** 重新打开最近关闭的标签。关闭的会话仍可从侧栏打开，后台任务会继续运行。

工作台重启时会恢复打开的标签、原顺序和上次选中的会话。已保存会话按 Codex 会话 ID 恢复，未发送的会话沿用本地草稿存档。指定 `--workspace` 启动时，当前视图优先打开指定目录，其他项目的标签也会恢复。标签记录保存在 Codex 主目录的 `xrack-workbench/conversation-tabs.json`。

在侧栏输入标题关键词，或按 Command/Control+K 聚焦搜索框，可搜索当前工作区的历史会话。打开已保存的会话后，点标题栏的 **会话操作（⋯） → 重命名** 修改名称。Codex 保存新名称，重启后也能按它搜索。

打开已保存的会话后，点 **会话操作（⋯） → 置顶**，或按 Command/Control+Alt+P，可把它移到当前项目的 **置顶** 区。再次操作会取消置顶。置顶仅影响 XRack 工作台，保存在 Codex 主目录的 `xrack-workbench/pins/`。重启时会按会话 ID 读取置顶项，历史列表无需先翻页。在工作台归档会话后，侧栏暂时隐藏该置顶项，恢复会话时会重新显示。

侧栏的 **命令** 和 Command/Control+Shift+P 都可打开命令面板。用方向键选择结果，按 Enter 执行。Command/Control+P 可按文件名或路径搜索当前工作目录。输入 `counter.xr:7` 可在打开文件时高亮第 7 行。Git 工作区索引已跟踪及未被忽略的文件，其他目录按文件树扫描。索引最多保留 5 万个路径，每次最多显示 60 条结果。

侧栏底部的外观图标和命令面板的 **更改外观** 可以切换浅色、深色或跟随系统，也可以选择 **简体中文** 或 **English**。切换即时生效，并保留当前会话和草稿。配色和界面语言分别保存在 Codex 主目录的 `xrack-workbench/appearance.txt` 和 `xrack-workbench/language.txt`，下次启动会沿用。默认使用简体中文。

在已保存会话的标题栏点 **会话操作（⋯） → 归档会话**，可将它移到侧栏的 **已归档**。在该视图中可以搜索和阅读当前工作区的归档会话。点 **恢复会话** 将会话移回活跃列表，然后可在原来的 thread 继续发送。

在标题栏点 **会话操作（⋯） → 创建分支**，可继承完整会话，或只继承到选中的已结束轮次。可先加载更早的消息以选择更早的轮次。归档会话需要先恢复。

完成的回复下方可点 **复制** 将 Markdown 原文写入系统剪贴板。顶层 Markdown 围栏代码会独立显示，点 **复制代码** 可复制块内文本并保留空行和缩进。对话搜索也可以定位块内的匹配行。点 **引用** 打开选区窗口，再将选中文字加入当前草稿。轮次的最后一条回复可点 **从此分支**，预选该轮作为新会话的继承终点。

已结束轮次的命令和执行计划默认折叠到 **本轮活动**。点击摘要可展开该轮的步骤，提示、回复和本轮改动仍可直接阅读。对话搜索会展开命中的活动，并滚到命令输出里的匹配行。

历史用户消息上的 **编辑** 会打开原提示文字。可把改写的文字追加到当前草稿。对于已结束轮次的第一条提示，也可选择 **创建分支草稿**，让分支继承该轮之前的上下文，并把改写的文字留在新分支的输入框。原会话和它的草稿可从侧栏返回。历史附件可以在新草稿中重新添加。

分支默认使用当前目录。勾选 **独立 Git 工作树** 后，工作台会从当前 HEAD 创建 detached worktree，并让新会话在该目录运行。可选 **带上原目录中已跟踪的改动**，将暂存区和工作区相对于 HEAD 的净改动复制为新工作树中的改动，补丁上限为 24 MiB。工作树保存在 Codex 主目录的 `xrack-workbench/worktrees`。

标题栏显示当前 Git 分支或分离的 HEAD。点分支名可搜索和切换本地分支，也可从当前提交创建并进入新分支。窄窗口在会话菜单中提供 **本地 Git 分支**。分支选择器会标记被其他工作树占用的分支。切换使用 Git 的普通检出规则，遇到会被覆盖的本地改动（含忽略文件）时会中止。切换成功后会刷新文件树、文件预览和改动面板。分离工作树支持 **在此创建分支**，便于接着提交、推送和创建 PR。

工作台在 Codex 主目录的 `xrack-workbench/forks` 保存轻量索引。重启后可找回尚未续聊的分支，也可从原项目找到关联的工作树会话。会话内容由 Codex 保存。

可拖动侧栏分隔线调整宽度。空白页的快捷问题会填写草稿。点 **发送**，或在输入框按 Command/Control+Enter 提交。阅读前面的消息时，流式输出会保留当前滚动位置。点输入区上方的 **回到最新** 或滚回底部，即可继续跟随输出。加载 **更早消息** 后会留在原先的阅读位置。

窗口较窄时，**文件** 和 **改动** 会占满工作区，便于阅读源码和差异。点 **返回对话** 或在面板中按 Esc，可回到原对话和草稿。编辑文件或审阅批注时，可用 **返回对话** 暂时收起面板。拉宽窗口会恢复分栏，已打开的文件和改动仍可继续查看。

点 **终端** 或按 Command/Control+J，可在当前工作目录打开交互式本机 Shell。点标签栏右侧的 **+** 创建更多终端，拖动可排序。按 Command+Option 或 Control+Alt 加 `[` / `]` 切换标签并聚焦输入。各标签保留自己的 Shell 和输出，切换工作目录后可回到原来的标签组。

终端通过系统 PTY 接收键盘输入、粘贴和窗口大小，支持 Ctrl+C、ANSI 前景色及每个标签 1500 行回看。点 **上一页** 或按 Shift+PageUp 查看历史，点 **回到底部** 回到实时输出。**隐藏** 保留全部会话，标签上的关闭按钮结束对应的 Shell，**重启** 只重新启动当前标签。终端使用当前用户权限运行。

在终端标题栏点 **引用输出** 可把当前可见页加入草稿。选中文字后按钮变为 **引用选段**，只附加所选内容。终端附件可预览或移除，随草稿保存，并在发送消息时交给 Codex。单项保留末尾至多 12 KiB，预览会标出截断。

常用命令可定义在当前工作目录的 `.xrack/actions.toml`。点终端标题栏的 **操作**，或在命令面板选择 **运行项目操作**，即可查看待执行的参数和目录。点 **运行** 会新建一个带操作名称的 PTY 标签，完成后保留输出和退出状态。

同一个操作面板也会列出项目根目录 `.codex/environments/*.toml` 的 `[[actions]]`。这些操作使用当前项目根目录，并支持按宿主平台选择命令。

```toml
[[action]]
id = "workbench-check"
name = "工作台测试"
argv = ["bazel", "test", "--repo_env=CARGO_BAZEL_ISOLATED=false", "//examples/agent-workbench:review_test"]
cwd = "."
```

`argv` 的第一项是程序名，其余各项按原样传给程序。`cwd` 可省略，默认使用当前工作目录。修改清单后点 **重新读取**。

按 Command/Control+F，或从命令面板选择 **在对话中查找**，可搜索已加载的正文、计划和命令输出。命中会标出并滚动到对应的一行。用 Command/Control+G 及 Command/Control+Shift+G 在匹配间移动，按 Esc 关闭查找栏。可以在查找栏加载 **更早消息**，新加入的消息会纳入当前结果。

输入区下方显示当前模型，宽窗下同时显示推理档位。点击模型按钮或按 **Ctrl+Shift+M** 可打开生成设置。选 **会话默认** 会沿用 Codex 的设置。指定模型后，可以选择它支持的推理档位。发送时会为该轮带上所选参数，Codex 将它们作为同一会话后续轮次的默认值。

在空输入框键入 **/** 可以就地搜索命令。用 **↑ / ↓** 移动，按 **Enter** 或点击执行，按 **Esc** 关闭并保留文字。命令包括 `/model`、`/plan`、`/review`、`/fork`、`/diff`、`/terminal` 和 `/find`，列表会按当前会话状态筛选。包含路径或正文的草稿沿用普通发送流程。

点输入区的 **用量** 查看 Codex 上报的最近测量与会话累计用量。收到上下文窗口大小后，按钮显示最近测量的占用比例。在空闲会话中点 **压缩上下文** 可发起 Codex 原生压缩，对话会显示完成标记。

当本机 Codex 提供计划和执行模式时，可以在生成设置里切换。计划模式中的澄清问题可逐题回答或略过，方案也会在对话中实时显示。点 **采用方案** 会切回执行模式并把方案加入草稿，确认草稿后再发送即可继续同一个 thread。

点输入框下方的快捷键提示，或从命令面板打开 **发送设置**。可以选 Command/Control+Enter 发送、单行用 Enter 发送，或用 Enter 发送单行和多行消息。Shift+Enter 可以换行。

输入框为空时，按 **↑** 可以找回本会话上一条提示的正文。继续用 **↑ / ↓** 浏览已加载的历史，按 Esc 回到空草稿。开始编辑后，方向键会恢复为普通光标操作。草稿中已有附件时，方向键仍用于编辑。

输入区自动将草稿保存到当前 Codex 主目录下的 `xrack-workbench/drafts/composer-drafts.json`。退出后打开原会话即可继续编辑。未发送过的新会话也会在对应项目的侧栏恢复。草稿随存的文本和选段会保留附加时的内容，图片和大型文件保留本地路径。附件被移动或删除时，输入区会提示重新选择。提交得到 Codex 确认后会清除已发送的草稿。

任务运行中可以将默认发送动作设为 **排队** 或 **追加**。主按钮和输入框里的 Command/Control+Enter 都执行默认动作。旁边的按钮与 Command/Control+Shift+Enter 执行另一种动作。排队会等待当前轮结束。追加会把消息送给当前轮。两项设置会保留到下次启动。停止当前轮会保留待发消息，可从列表移除或选择发送。打开带有待发消息的旧会话时，可以先 **接回队列**。

在输入框上方的队列里，可用 **↑ / ↓** 调整发送顺序，点 **编辑** 修改待发消息正文。保存保留原有附件和技能，当前输入框的草稿也会保留。来自其他客户端的结构化正文提供只读预览。编辑期间如果消息已发送或被改动，弹窗会保留本次编辑的文字，便于复制。

点输入区的 **附件** 可多选文件，在支持文件拖放的宿主上也可直接拖到输入框。附件随草稿保存，可在发送前移除。大小不超过 4 MiB 且不超过 1600 万像素的 PNG 可查看缩略图和大图。图片通过 Codex 的本地图片接口发送。每条消息可带至多 8 个附件，UTF-8 文本可内联到上下文中，每个文件最多 12 KiB，合计最多 24 KiB。超出文本范围的文件按路径交给 Codex。附件可随普通发送、追加或排队提交。

在输入框键入 `@` 和部分文件名，可搜索当前工作区的文件。点击候选，或用上下方向键选中后按 Enter，即可附加文件。附件添加成功后，仅移除对应的 `@` 查询。按 Esc 收起候选并保留草稿。

在输入框键入 `$` 和部分名称，可查看 Codex 为当前工作目录发现并启用的技能。用方向键和 Enter 或点击选择，技能会作为可移除项加入草稿，发送时通过 Codex 原生技能输入传递。技能可随草稿恢复，也可随消息排队或追加。同名技能的候选项会显示各自的文件路径。

Codex 报告的计划和命令会按收到顺序出现在对话内。计划更新保留在同一张卡片里。连续多条命令默认收起，摘要显示命令总数、进行中和失败的数量。点摘要展开列表，再点单条命令查看实时输出和退出状态。对话搜索命中收起的输出时会自动展开对应命令。展开后暂停自动跟随，每条命令最多预览 8 KiB 输出。

如果一轮对话收到了 Codex 的改动报告，点击消息中的 **本轮改动** 可以查看该轮报告的文件、增删行数和 diff。面板会随该轮报告更新。点击 **看工作区** 可以切换到当前 Git 仓库，那里可以分别查看已暂存、未暂存和新增文件。也可以从对话标题右侧的 **改动** 或 Command/Control+Shift+D 直接打开工作区改动。窗口较窄时，可收起会话侧栏。

工作区改动默认使用 **全部**。通过 **未暂存** 或 **已暂存** 只查看对应的文件和差异。同一个文件既有暂存又有未暂存的内容时，会分别出现在两个视图里。选中文件后可点 **暂存文件** 或 **取消暂存**，操作只更新所选文件在 Git 索引中的内容。面板随后刷新文件列表和各视图的数量。

暂存后，可在改动面板点 **提交**。弹窗显示当前分支或分离的 HEAD，以及待提交文件。填写提交说明并确认后，工作台重新校验分支和暂存区，使用项目原有的 Git 提交流程创建本地提交。暂存内容发生变化或 Git 返回错误时，说明会留在弹窗里，可以重新读取暂存区后再试。

在改动面板点推送图标，或在提交完成后点 **推送**，可查看将要推送的提交、远端及目标分支。可以使用已有上游，也可以选择其他远端并填写新分支。分离 HEAD 时需填写目标分支。有本地分支时可以勾选设置上游。工作台确认后执行普通 Git 推送，远端领先时由 Git 拒绝更新。

推送完成后可点 **创建 PR**，也可从改动面板打开入口。工作台用已登录的 GitHub CLI（`gh`）确认源分支，支持本仓库和 fork 的目标仓库。填写目标分支、标题和说明后可以创建普通 PR 或草稿。相同源分支和目标已有开放 PR 时会返回现有链接。使用 GitHub Enterprise 时，工作台使用 GitHub CLI 为该主机保存的凭据。

在带行号的普通文本差异里，每个差异块的标题提供 **暂存这块** 或 **取消暂存这块**。Git 差异变动后，面板会刷新并请你重新选择差异块。新增、删除、重命名、二进制文件以及被截断的差异可使用文件级操作。

普通已跟踪文本文件的未暂存差异提供 **回退文件** 和 **回退这块**。先复查确认页显示的补丁，再点 **确认回退**，将选定范围恢复到 Git 索引中的内容。工作台在写入前核对补丁和磁盘文件，差异变化时会要求刷新后重新选择。

在差异标题栏点 **并排**，可对照旧版本与新版本。连续删除和新增按差异块对齐，未配对的一侧留空。点击任一栏的行号会把批注定位到该版本。块标题沿用原差异块的暂存操作。点 **单栏** 可切回带行号的统一视图，**原文** 可查看完整补丁。窄窗会用整个窗口显示并排审阅。

点 **查找**，或在审阅面板有焦点时按 **Command/Control+F**，可搜索当前补丁。原文中选中的单行文字会作为初始查询。用 **Enter**、**Shift+Enter** 或查找栏的箭头浏览匹配，切换单栏、并排和原文会定位到同一匹配。按 **Esc** 关闭查找。

工作区的未暂存文本差异和未跟踪文本文件会在新版本行右侧显示 **编辑**。可以在审阅中改写该行，也可以输入多行。点 **保存到工作区** 或按 **Command/Control+S** 提交文件修改并刷新补丁。保存前会比对磁盘文件，发生冲突时保留编辑草稿。

点 **比较版本** 可选择基准分支或输入提交 SHA、标签及其他 Git 提交引用。分支视图比较共同祖先与当前提交，提交视图比较所选提交与其第一个父提交。第一次提交会显示它新增的内容。点 **查看版本源码** 会打开差异对应的 Git 文件，删除的文件可从旧版本查看。行内批注会带上比较范围和提交 ID。点 **看工作区** 返回未提交改动。

点击 diff 的行号可写审阅批注。**加入草稿** 会把这条批注连同文件、行号和差异来源写入当前消息。也可以点 **暂存批注**，继续审阅其他行或文件。点 **N 条暂存批注** 可复查、编辑或移除，点 **全部加入草稿** 后可在发送前统一调整。暂存批注随会话草稿保存。查看长行或需要复制时，点 **原文** 切换到可选中的差异文本。

点标题栏右侧的 **文件** 图标或按 Command/Control+Shift+E 打开右侧文件树。目录在展开时读取，支持键盘导航。选中文件可以查看带行号的 UTF-8 源码、Markdown 或 PNG。也可以从差异头部点 **查看源码** 打开当前工作树里的文件，切回 **改动** 后保留原来的批注和差异位置。预览只访问当前工作目录内的文件，超过预览上限时会显示提示。

回复和计划里的文件引用可以直接点击，也可以用 Tab 聚焦后按 Enter。支持行内代码和 Markdown 链接，例如 `src/main.rs:42`、`src/main.rs:42:5` 或 `src/main.rs#L42-L46`。文件面板会打开引用位置并高亮对应行。点 **从头查看** 可回到文件开头。定位行号时最多扫描文件开头 8 MiB。

在会话标题、文件预览或工作区差异里点「打开方式」图标，可将工作目录或磁盘文件交给 VS Code、Cursor 或系统文件管理器。从对话引用进入文件预览时，行列位置会传给编辑器。勾选「记住此项目的打开方式」可保存默认选项，项目下的工作树也会沿用该选项。应用将设置保存在 Codex 主目录的 `xrack-workbench/external-open.toml`。

在文件树、改动面板和对话里打开的同一个文件会共用标签。同一窗口里每个工作目录保留自己的标签顺序、引用行和滚动位置。可以拖动标签排序，用方向键切换，或点击关闭按钮。在标签上按 Delete 也可关闭。关闭当前文件后会切到相邻标签。点 **刷新** 可重新读取目录和当前预览。

文本文件可在预览标题旁点 **编辑**。支持最多 1 MiB 的 UTF-8 文件，包括 Markdown。点 **保存** 或按 Command/Control+S 写入。保存前会比较磁盘上的完整文件，发现外部修改时保留草稿。草稿随文件标签保存在当前窗口内，关闭有未保存修改的标签或退出工作台前会提示确认。手动编辑使用当前用户的文件访问权限，Codex 的沙箱模式由启动参数单独控制。

在文件面板底部点 **附加文件** 可把当前磁盘文件加入对话草稿。编辑时这个按钮叫 **附加磁盘文件**。在源码预览或编辑器选中文字后，点 **加入选段** 可仅附带选中的内容和原文件行号。未保存的代码会显示为 **草稿选段**。渲染后的 Markdown 摘录会附带选中的显示文本。选段沿用附件的数量与文本体积限制，添加后仍可从输入区移除，发送时才交给 Codex。

从标题栏的 **会话操作（⋯） → 发起代码审阅**、工作区改动里的 **发起审阅** 或 Command/Control+Shift+R 发起 Codex 代码审阅。可以审阅未提交改动、与本地或远程跟踪分支对比，或指定一个 Git 提交。审阅在当前会话中运行，保留输入框草稿。完成后点对话里的 **查看报告**，点击审阅意见中的文件位置可查看当前 Git 工作树中对应的源码片段。重新打开会话也能查看报告。

示例通过 stdio 连接 Codex App Server，历史消息由 Codex 保存。工作台从历史中恢复消息和命令输出，执行计划的进度和每轮聚合 diff 保留在当前窗口。启动时默认使用只读沙箱。需要让 Codex 编辑文件时，在启动命令末尾显式加上 `--workspace-write` 来使用 Codex 的工作区写入沙箱。当前权限显示在输入框下方。控件可以显示基础 Markdown，并对暂时不完整或不支持的 Markdown 显示原文。

```sh
bazel test --repo_env=CARGO_BAZEL_ISOLATED=false \
  //examples/agent-workbench:session_test \
  //examples/agent-workbench:review_test \
  //examples/agent-workbench:workbench_parity_test
```

协议回归使用模拟服务器消息，UI 回归用同一份 `.xr` 对照 Rust AOT 和 MLIR 解释器。

长对话滚动基准使用 120 条中英混排的 Markdown 消息，分别统计场景布局和加入滚动回调后的耗时。用同一台机器和字体配置进行前后对照。

```sh
bazel test //examples/agent-workbench:workbench_render_test -c opt --nocache_test_results \
  --test_arg=--ignored --test_arg=--nocapture \
  --test_arg=long_transcript_scroll_benchmark --test_output=all
```

GPU 基准使用 2 倍像素比例绘制到离屏纹理。分别测纯滚动和边滚动边更新最后一条回复，报告模型更新、场景生成、布局、绘制提交、GPU 等待和整帧的 p50、p95。加上 `--test_env=XRACK_TRANSCRIPT_BENCH_LATEST=1` 会让流式更新阶段跟随最新回复，测试视口内文字持续变化的情况。可用 `--test_env=XRACK_TRANSCRIPT_BENCH_ROUNDS=20` 延长运行时间，便于采样 CPU 调用栈。

```sh
bazel test //examples/agent-workbench:workbench_render_test -c opt --nocache_test_results \
  --test_arg=--ignored --test_arg=--nocapture \
  --test_arg=transcript_gpu_benchmark --test_output=all
```

## 界面模块与翻译

`workbench.xr` 是主窗口入口，组装分栏、组件状态和 Rust 宿主接口。会话顶栏放在 `ui/header.xr`，对话内搜索和欢迎页放在 `ui/transcript.xr`，历史消息编辑和引用放在 `ui/message_dialogs.xr`。审阅报告、工作区关闭确认、工作树设置和终端也各有组件入口。新增模块时，把源文件加入 `BUILD.bazel` 的 `WORKBENCH_SOURCES`。

入口通过 `translations "i18n/catalog.toml"` 加载 Fluent 语言包。各模块使用 `@tr("message-id")` 引用同一组词条，Bazel 会将中英语言包嵌入生成的 Rust。Rust 会话协议通过 `Status` 传递状态，`workbench-status` 词条按当前语言显示连接、回复、停止、审阅和压缩等状态。增加界面文案时，同时更新 `i18n/zh-CN.ftl` 和 `i18n/en-US.ftl`。会话正文、项目名称和外部工具输出按来源显示。
